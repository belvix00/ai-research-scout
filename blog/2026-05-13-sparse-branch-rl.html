Sparse Branch Selection: When Reasoning RL Is Mostly Probability Mass Reallocation

Why this concept appeared in the scout

The 2026-05-12 scout had a unusually clean post-training cluster:

  • ReasonMaxxer / Rethinking RL for LLM Reasoning claimed that much of the observed reasoning-RL gain is localized: only a small fraction of high-entropy token positions change, and the promoted token is often already among the base model's top alternatives.
  • GraphDPO argued that preference data for one prompt is often a directed graph over rollouts, not a bag of independent pairs.
  • Listwise Policy Optimization made the response-simplex target of group RLVR explicit.
  • KL for a KL / vOPD imported a closed-form control-variate baseline into on-policy distillation.

Together these are not just four new optimizer recipes. They point at a mechanism question:

Is post-training teaching a new reasoning algorithm, or is it mostly reallocating probability mass among branches already present in the base model?

This post is a foundations refresher on that question. The goal is not to re-explain PPO, DPO, or transformers. It is to pin down the geometry of sparse branch selection: high-entropy decision points, response-simplex targets, graph/listwise supervision, and the measurements that would falsify the claim.

The prior rollout-lifecycle post [[2026-05-07-rollout-lifecycle-gradient]] treated the whole sampled trajectory distribution as the object. This post zooms into one narrower hypothesis: conditional on having sampled useful trajectories, the useful update may live at a small set of branch points.

A rollout can improve because one branch changed

Let a reasoning trace or solution be a token sequence

$$y = (y_1,\ldots,y_T),$$

sampled from a base policy

$$\pi_0(y\mid x)=\prod_{t=1}^{T}\pi_0(y_t\mid x,y_{<t}).$$

A post-trained policy $$\pi_\theta$$ improves a task if it increases probability of successful traces:

$$P_\theta(\mathrm{success}\mid x) = \sum_y \pi_\theta(y\mid x)\,\mathbf{1}[R(x,y)=1].$$

That probability can rise in two very different ways.

  1. Distributed algorithmic change: many token distributions move, hidden states reorganize, and success probability improves because the model computes differently across the trace.
  2. Sparse branch selection: most conditional distributions stay close to the base model, but at a few uncertain positions, probability mass moves from a bad branch to a good branch.

The second case is easy to understate because the final trace may look very different after one early branch. A single token such as therefore, a sign choice, an intermediate variable, a tool call, or a decomposition step can route the rest of the trajectory.

For a prefix $$h_t=(x,y_{<t})$$, define the base-model entropy

$$H_0(h_t) = -\sum_{v}\pi_0(v\mid h_t)\log \pi_0(v\mid h_t).$$

Sparse branch selection says the main update is concentrated on a subset

$$B(x,y) = \{t: H_0(h_t)>\tau_H,\; \Delta_t \text{ affects outcome}\},$$

with $$|B|\ll T$$. The post-training distribution can then have low average KL while still producing large task gains.

Why small token KL can still mean large outcome change

Per-token KL from the base policy is

$$D_{\mathrm{KL}}(\pi_\theta\|\pi_0 \mid h_t) = \sum_v \pi_\theta(v\mid h_t)\log\frac{\pi_\theta(v\mid h_t)}{\pi_0(v\mid h_t)}.$$

The sequence-level KL decomposes as

$$D_{\mathrm{KL}}(\pi_\theta(y\mid x)\|\pi_0(y\mid x)) = \mathbb{E}_{y\sim\pi_\theta}\left[\sum_{t=1}^{T} D_{\mathrm{KL}}(\pi_\theta(\cdot\mid h_t)\|\pi_0(\cdot\mid h_t))\right].$$

If only $$k$$ positions change, the average per-token KL can look tiny:

$$\frac{1}{T}\sum_t D_t \approx \frac{1}{T}\sum_{t\in B}D_t.$$

But task success is not linear in average token KL. If an early branch chooses between two basins of continuation, moving one conditional probability can multiply the mass of successful completions.

Suppose at prefix $$h$$ the base model assigns probability $$p_0$$ to a good branch $$a^+$$ and $$1-p_0$$ to a bad branch $$a^-$$. Let continuation success probabilities be

$$S^+ = P(\mathrm{success}\mid h,a^+),\qquad S^- = P(\mathrm{success}\mid h,a^-),$$

with $$S^+\gg S^-$$. If post-training changes only that branch probability to $$p_\theta$$, then

$$P_\theta(\mathrm{success}\mid h)-P_0(\mathrm{success}\mid h) = (p_\theta-p_0)(S^+-S^-).$$

So a local probability shift has large value when two conditions hold:

$$|p_\theta-p_0| \text{ is nontrivial} \quad\text{and}\quad S^+-S^- \text{ is large}.$$

This is the precise version of “the base model already knew the branch.” The branch must be in support, and the continuation gap must be high.

The gradient concentrates where alternatives disagree

Consider a policy-gradient style update for a sampled token $$a_t$$ at prefix $$h_t$$:

$$g_t = \widehat{A}_t\nabla_\theta \log \pi_\theta(a_t\mid h_t).$$

For logits $$z_v(h_t)$$, the derivative has the familiar softmax form:

$$\frac{\partial \log \pi(a_t\mid h_t)}{\partial z_v} = \mathbf{1}[v=a_t]-\pi(v\mid h_t).$$

So the logit-gradient component is

$$\frac{\partial \mathcal{L}_{\mathrm{PG}}}{\partial z_v} = -\widehat{A}_t\left(\mathbf{1}[v=a_t]-\pi(v\mid h_t)\right)$$

for gradient descent on $$-\widehat{A}_t\log\pi(a_t\mid h_t)$$.

If $$\widehat{A}_t>0$$, the sampled token's logit rises and competing logits fall. If $$\widehat{A}_t<0$$, the sampled token is suppressed. The update is only useful when sampled alternatives have different downstream value. At a deterministic low-entropy prefix, most rollouts choose the same token and local credit cannot distinguish branches. At a high-entropy prefix with outcome-sensitive alternatives, the same estimator becomes a branch-ranking signal.

Define a local value for choosing token $$v$$:

$$Q(h,v)=\mathbb{E}[R(y)\mid h_t=h, y_t=v].$$

The expected logit-gradient direction at prefix $$h$$ is proportional to

$$\mathbb{E}_{v\sim\pi}\left[(Q(h,v)-b(h))\nabla_z\log \pi(v\mid h)\right].$$

Using the softmax derivative, the expected gradient for logit $$z_u$$ becomes

$$\mathbb{E}\left[(Q(h,v)-b)(\mathbf{1}[u=v]-\pi(u\mid h))\right] = \pi(u\mid h)\left(Q(h,u)-\bar{Q}(h)\right),$$

where

$$\bar{Q}(h)=\sum_v \pi(v\mid h)Q(h,v).$$

This equation is the branch-selection core:

$$\Delta z_u \propto \pi(u\mid h)\left(Q(h,u)-\bar{Q}(h)\right).$$

A token gains logit if its continuation value is above the local average. It loses logit if below. The multiplicative $$\pi(u\mid h)$$ term also explains why post-training can be efficient when the good answer is already in the top-k: if $$\pi(u\mid h)$$ is not tiny, the gradient can reach it. If the needed token is outside support, sparse branch selection fails.

DPO is also local odds shifting

DPO-like objectives make the odds-shift interpretation even clearer. For a prompt $$x$$ with preferred response $$y^+$$ and dispreferred response $$y^-$$, the DPO loss is commonly written as

$$\mathcal{L}_{\mathrm{DPO}} = -\log \sigma\left(\beta\left[ \log\frac{\pi_\theta(y^+\mid x)}{\pi_0(y^+\mid x)} - \log\frac{\pi_\theta(y^-\mid x)}{\pi_0(y^-\mid x)} \right]\right).$$

Because sequence log-probability decomposes by token,

$$\log \pi_\theta(y\mid x)=\sum_t\log\pi_\theta(y_t\mid x,y_{<t}),$$

the DPO margin is a sum of token-level log-ratio changes:

$$M_\theta = \sum_t \Delta^+_t - \sum_s \Delta^-_s,$$

where

$$\Delta^+_t=\log\frac{\pi_\theta(y^+_t\mid h^+_t)}{\pi_0(y^+_t\mid h^+_t)}, \qquad \Delta^-_s=\log\frac{\pi_\theta(y^-_s\mid h^-_s)}{\pi_0(y^-_s\mid h^-_s)}.$$

The loss does not inherently know which token caused the preference. If the winning and losing responses share a long prefix and diverge at one branch, DPO pressure naturally concentrates near the divergent region. If they differ everywhere in style and length, the same objective may spread credit across formatting, verbosity, or superficial trace features.

This is why graph/listwise structure matters. It can reduce arbitrary pair credit by using more of the rollout set's relative order.

Graph and listwise objectives as response-simplex targets

For one prompt, suppose we sampled $$n$$ candidate responses $$y_1,\ldots,y_n$$. The policy induces a distribution over this finite candidate set:

$$p_\theta(i\mid x) = \frac{\pi_\theta(y_i\mid x)}{\sum_{j=1}^n \pi_\theta(y_j\mid x)}.$$

A pairwise objective says some edges should have positive margins:

$$y_i \succ y_j.$$

A graph/listwise objective tries to construct a target distribution $$q(i\mid x)$$ over candidates, then move $$p_\theta$$ toward it. Abstractly:

$$\min_\theta D(q(\cdot\mid x)\,\|\,p_\theta(\cdot\mid x))$$

or the reverse/regularized variant depending on the method. The important object is the target on the response simplex:

$$\Delta^{n-1}=\left\{p\in\mathbb{R}^n: p_i\ge 0,\;\sum_i p_i=1\right\}.$$

For example, a Plackett-Luce-style ranking model uses scores $$s_i$$ and probabilities

$$P(i \text{ ranked first})=\frac{\exp(s_i)}{\sum_j\exp(s_j)}.$$

If the supervision graph implies layers of equivalent responses, the target need not collapse all mass onto one winner. It can distribute probability over equivalent good branches and suppress dominated branches:

$$q_i \propto \exp(r_i/\tau),$$

where $$r_i$$ is a graph-derived score or rank. This matters for reasoning because there may be many valid traces. A one-winner target can unnecessarily destroy diversity; a graph/listwise target can preserve multiple good branches while demoting inconsistent or wrong ones.

The simplex view also clarifies why “RLVR vs DPO vs listwise” is not the deepest distinction. The deeper question is:

What target distribution over branches did the data and objective induce, and how much did the model have to move to reach it?

Sparse branch selection as a measurable decomposition

We can turn the hypothesis into a decomposition. Let

$$\delta_t(h_t) = D_{\mathrm{KL}}(\pi_\theta(\cdot\mid h_t)\|\pi_0(\cdot\mid h_t)).$$

Let $$G$$ be a set of successful post-training rollouts. Define the cumulative KL budget over their prefixes:

$$K(G)=\mathbb{E}_{y\in G}\left[\sum_{t=1}^{T}\delta_t(h_t)\right].$$

If sparse branch selection is true, then a small top-m subset of positions should explain most of the KL movement:

$$\frac{\sum_{t\in \mathrm{TopM}(\delta)}\delta_t}{\sum_{t=1}^{T}\delta_t}\approx 1 \quad\text{for small } m/T.$$

But KL concentration alone is insufficient. The changed positions must be outcome-sensitive. For a changed prefix $$h_t$$, estimate a branch value gap:

$$\Gamma(h_t)=\max_{u,v\in \mathrm{TopK}_0(h_t)} |\widehat{Q}(h_t,u)-\widehat{Q}(h_t,v)|.$$

The sparse-branch story predicts high movement where both base entropy and branch value gap are high:

$$\delta_t \text{ large } \Rightarrow H_0(h_t)\text{ high and }\Gamma(h_t)\text{ high}.$$

If instead high movement appears mostly in boilerplate, final-answer formatting, verbosity, or style tokens with low branch value gap, then the update is not a clean reasoning-branch update.

When sparse branch selection fails

The hypothesis is attractive because it suggests cheap post-training and clear diagnostics. But it has sharp failure conditions.

1. The good branch is not in support

The expected logit update has a $$\pi(u\mid h)$$ factor. If the useful branch has near-zero base probability, ordinary on-policy branch selection barely reaches it:

$$\pi_0(u\mid h)\approx 0 \quad\Rightarrow\quad \Delta z_u \approx 0.$$

Then you need support expansion: better SFT traces, search, synthetic data, tool use, verifier-guided exploration, or architectural change.

2. The correct computation requires hidden-state reorganization

Some gains are not local token choices. If the model lacks a representation for a variable binding, proof invariant, latent plan, or tool state, shifting probability among existing tokens is not enough. You would expect broad activation changes, improved probes, and token distribution changes across many positions.

3. Pairwise labels credit the wrong feature

If $$y^+$$ and $$y^-$$ differ in correctness and also in style, length, or formatting, a pairwise objective can learn the correlated superficial dimension. This is one reason graph/listwise/equivalence-class structure is useful: it can separate “good because correct” from “good because verbose.”

4. Entropy is not value uncertainty

High entropy only means the model is uncertain among tokens. It does not mean the alternatives have different outcome value. A high-entropy adjective choice may be irrelevant. A low-entropy but wrong deterministic step may be the real bottleneck.

So entropy-gated training needs an outcome or verifier signal, not entropy alone.

What to measure

For a small reasoning/post-training run, log the update geometry directly:

  1. Changed-token sparsity
$$ \delta_t = D_{\mathrm{KL}}(\pi_\theta(\cdot\mid h_t)\|\pi_0(\cdot\mid h_t))$$

and the fraction of total KL explained by the top 1%, 3%, 5%, and 10% positions.

  1. Base-rank of promoted tokens

For tokens whose probability rises most, record their rank under $$\pi_0(\cdot\mid h_t)$$. Sparse branch selection predicts many promoted reasoning tokens are already top-k.

  1. Entropy/value overlap

Measure whether changed positions have high base entropy $$H_0(h_t)$$ and high estimated branch value gap $$\Gamma(h_t)$$.

  1. Response-simplex movement

For each prompt's sampled candidate set, compare the induced pre/post candidate distributions:

$$ p_0(i\mid x),\quad p_\theta(i\mid x),\quad q(i\mid x).$$

Plot whether training moves toward the graph/listwise target or collapses onto one response.

  1. Activation vs logit locality

If hooks are cheap, compare activation drift across layers at changed and unchanged prefixes. Local logit shifts with small hidden drift support the branch-selection story; broad hidden reorganization argues against it.

  1. Diversity preservation

Count how many distinct correct strategies remain probable after training. A good listwise/graph target should demote bad branches without unnecessarily eliminating equivalent good branches.

Minimal experiment

Use a fixed small model and a small math/code reasoning set where multiple rollouts per prompt can be sampled and verified.

  1. Sample $$n$$ base rollouts per prompt with logprobs.
  2. Build a per-prompt outcome graph: correct beats incorrect; shorter or cleaner correct traces may beat bloated correct traces only if that preference is intended; equivalent correct traces stay tied.
  3. Train four variants under the same prompts and candidate pool:

- pairwise DPO on randomly chosen winner/loser pairs;

- graph/listwise objective over all sampled candidates;

- entropy-gated contrastive correction only at high-entropy divergent prefixes;

- SFT on winners as a blunt baseline.

  1. Evaluate task accuracy, calibration, diversity of correct strategies, and the measurements above: KL concentration, promoted-token base rank, entropy/value overlap, and candidate-simplex movement.

A clean falsifier would be:

$$\text{accuracy gains require broad KL movement or promoted tokens outside base top-k.}$$

Another falsifier: entropy-gated corrections reproduce training-set gains but fail badly out of distribution, implying that branch selection overfit surface divergences rather than learning reusable decision rules.

Failure modes

  1. Support illusion. The correct branch appears in top-k on easy prompts but not on the hard prompts where RL matters.
  2. Style-credit leakage. Preference labels reward formatting, confidence, or verbosity correlated with correctness; sparse updates then target style branch points.
  3. Entropy trap. High-entropy positions are selected even when alternatives have low outcome value gap.
  4. Diversity collapse. A pairwise or low-temperature listwise target puts all mass on one trace and destroys alternative valid strategies.
  5. Verifier-induced branch bias. The verifier prefers traces it can parse, not traces that are causally better reasoning.
  6. Hidden distributed learning. The method appears sparse at logits, but activation probes reveal broad representation changes; the branch-selection explanation is incomplete.
  7. Candidate-pool ceiling. Offline candidate sets omit the branch that would solve harder examples; graph/listwise training can only re-rank what was sampled.

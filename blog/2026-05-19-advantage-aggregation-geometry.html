Advantage Aggregation: Where Sequence Rewards Become Token Gradients

Why this concept appeared in the scout

The 2026-05-19 scout had a tight reasoning-RL cluster:

  • Nudging Beyond the Comfort Zone emphasized that RLVR cannot reinforce strategies the model never samples.
  • Hölder Policy Optimisation made the sequence-to-token mapping itself a research object rather than an implementation detail.
  • GRLO and MetaAgent-X widened the setting from math-answer RLVR to open-ended and workflow-level optimization.
  • The running notes keep converging on the same measurement problem: hold rollouts fixed, then ask how objectives move probability mass over prefixes, strategies, and event traces.

The previous post [[2026-05-13-sparse-branch-rl]] focused on whether post-training mostly reallocates probability mass among already-sampled branches. This post zooms into the next layer down:

Given a trajectory-level reward or preference, what operator turns that sequence signal into token-level gradient, and how does that operator change the geometry of the update?

This is not a beginner refresher on policy gradients. Aman already knows the stack. The useful foundations object is the credit map from sequence outcomes to token log-prob updates: uniform sequence credit, normalized sequence credit, token teachers, rubric decomposition, value baselines, listwise objectives, and Hölder/p-norm-style aggregators are different ways of choosing this map.

The hidden operator: from trajectories to token weights

Let a response or reasoning trajectory be

$$y=(y_1,\ldots,y_T),$$

with policy

$$\pi_\theta(y\mid x)=\prod_{t=1}^T \pi_\theta(y_t\mid h_t), \qquad h_t=(x,y_{<t}).$$

A sequence-level objective usually gives one scalar score, reward, or advantage:

$$A(y) = R(y)-b(x).$$

The most direct policy-gradient estimator uses

$$g_{\mathrm{seq}}(y)=A(y)\nabla_\theta \log \pi_\theta(y\mid x) = A(y)\sum_{t=1}^{T}\nabla_\theta \log \pi_\theta(y_t\mid h_t).$$

This equation quietly makes a strong credit-assignment choice: every sampled token in the successful trajectory inherits the same scalar advantage. The final answer was correct, so the opening phrase, the useful decomposition, the irrelevant filler, and the lucky arithmetic step all receive positive credit.

More generally, define a token credit map

$$C: A(y) \mapsto (a_1,\ldots,a_T),$$

and use

$$g_C(y)=\sum_{t=1}^{T} a_t(y)\nabla_\theta \log \pi_\theta(y_t\mid h_t).$$

Uniform sequence credit is the special case

$$a_t(y)=A(y).$$

Length-normalized credit might use

$$a_t(y)=\frac{A(y)}{T}.$$

A verifier or teacher with step labels might use

$$a_t(y)=\widehat{A}_t.$$

A rubric decomposition might use a sparse mixture:

$$a_t(y)=\sum_{k} \lambda_k r_k(y)\,m_{k,t}(y),$$

where $$r_k$$ is a rubric component and $$m_{k,t}$$ says which token, step, or event the component should touch.

The point: when two papers claim different RLVR improvements, the actual difference may be less “new optimizer” and more “different credit map $$C$$.”

Why uniform sequence credit has a geometry, not just variance

For logits $$z_v(h_t)$$, the gradient of a sampled token log-probability is

$$\frac{\partial \log \pi(y_t\mid h_t)}{\partial z_v(h_t)} =\mathbf{1}[v=y_t]-\pi(v\mid h_t).$$

With token credit $$a_t$$, gradient descent on

$$\mathcal{L}_C(y)=-\sum_t a_t\log\pi_\theta(y_t\mid h_t)$$

gives logit gradient

$$\frac{\partial \mathcal{L}_C}{\partial z_v(h_t)} = -a_t\left(\mathbf{1}[v=y_t]-\pi(v\mid h_t)\right).$$

So $$a_t$$ does not merely scale the update. It selects where probability mass moves.

If $$a_t>0$$, the sampled token is promoted against its local alternatives. If $$a_t<0$$, it is demoted. If $$a_t=0$$, that prefix receives no direct likelihood pressure. Therefore a credit map defines a field over prefixes:

$$h_t \mapsto a_t\,\nabla_\theta\log\pi(y_t\mid h_t).$$

Uniform sequence credit spreads this field across all tokens in a winning rollout. That can be correct if the whole trace is causally useful. But in reasoning traces, only a few positions may decide the outcome: a decomposition, a branch, a tool call, a stopping decision, or a correction. The uniform map then produces two pathologies:

  1. Credit dilution: the decisive branch receives only one unit of credit among many non-decisive tokens.
  2. Credit pollution: stylistic or incidental tokens get reinforced because they co-occurred with success.

Length normalization fixes one bias but creates another. If

$$a_t=\frac{A}{T},$$

then long successful traces do not automatically have larger total update norm, but every decisive token in a long trace also receives smaller local pressure. If a correct solution requires a long setup plus one key branch, normalization can under-train the branch.

A useful scalar is the branch credit share. For a set of outcome-sensitive positions $$B(y)$$,

$$\mathrm{Share}_B(C;y)=\frac{\sum_{t\in B(y)} |a_t|}{\sum_{t=1}^{T}|a_t|}.$$

Sparse branch-selection methods implicitly want this share to be high. Uniform sequence credit gives

$$\mathrm{Share}_B=\frac{|B|}{T}.$$

If $$|B|\ll T$$, the update geometry is mostly pointed somewhere else.

The expected update: value contrast times policy support

To see what an ideal local credit signal would do, define the continuation value at prefix $$h$$:

$$Q(h,v)=\mathbb{E}[R(y)\mid h_t=h, y_t=v].$$

The expected softmax-logit update for token $$u$$ under a local advantage $$Q(h,v)-b(h)$$ is proportional to

$$\mathbb{E}_{v\sim\pi}\left[(Q(h,v)-b(h))(\mathbf{1}[u=v]-\pi(u\mid h))\right].$$

Choosing $$b(h)=\bar Q(h)=\sum_v \pi(v\mid h)Q(h,v)$$ yields

$$\Delta z_u(h) \propto \pi(u\mid h)\left(Q(h,u)-\bar Q(h)\right).$$

This equation is the local target that sequence-level RL is trying to approximate with much weaker information. It says three things.

First, a token only receives useful positive update if its continuation value is above the local average. Second, the update is multiplied by $$\pi(u\mid h)$$, so unsupported strategies are hard to discover from reweighting alone. Third, the right credit is prefix-local; it depends on what alternatives were available at that state, not only whether the final sequence won.

This is why strategy-coverage papers and aggregation-geometry papers are complementary. Exploration changes which $$u$$ enter support. Aggregation changes how the reward signal is distributed once candidates are present.

Sequence-level objectives can be viewed as projections of the ideal credit

Let $$q_t$$ be the unknown ideal local advantage at each token:

$$q_t = Q(h_t,y_t)-\bar Q(h_t).$$

A practical objective chooses an approximate credit vector

$$a=(a_1,\ldots,a_T).$$

The quality of the credit map is not just its scalar reward correlation. It is the alignment between the produced gradient and a better reference gradient:

$$\cos(g_C,g_*)= \frac{\langle g_C,g_*\rangle}{\|g_C\|\|g_*\|}.$$

If we ignore parameter-sharing for a moment and treat token-gradient directions as locally orthogonal, this reduces approximately to credit-vector alignment:

$$\cos(g_C,g_*)\approx \frac{\sum_t a_t q_t \|\nabla\log\pi_t\|^2}{ \sqrt{\sum_t a_t^2\|\nabla\log\pi_t\|^2} \sqrt{\sum_t q_t^2\|\nabla\log\pi_t\|^2}}.$$

Uniform sequence credit is good only when the decisive local advantages have the same sign across most of the trajectory. It is bad when a winning trace contains wrong-but-recovered steps, irrelevant explanations, or a lucky final correction. Dense teachers are good only if their token labels correlate with $$q_t$$ rather than merely copying a stale teacher trace.

This framing also explains why old-logit fidelity matters. Many preference/RL objectives include a KL term to a reference policy:

$$\mathcal{L}= -\sum_t a_t\log\pi_\theta(y_t\mid h_t) +\beta\sum_t D_{\mathrm{KL}}\left(\pi_\theta(\cdot\mid h_t)\|\pi_{\mathrm{ref}}(\cdot\mid h_t)\right).$$

If $$\pi_{\mathrm{ref}}$$ is stale, approximated, or collected under a different runtime path, then the trust-region geometry is wrong at exactly the positions where credit is being assigned. The optimizer is not just maximizing reward; it is solving a constrained movement problem in the wrong local coordinate system.

Hölder / p-norm aggregation as a choice about concentration

Without relying on any one paper's exact notation, it is useful to think about aggregation rules as choosing a norm over token or step advantages. Suppose a trajectory exposes nonnegative local evidence magnitudes

$$s_t \ge 0,$$

perhaps from verifier gaps, teacher confidence, value errors, or branch disagreement. A p-norm aggregator has the shape

$$S_p(s)=\left(\sum_{t=1}^{T} s_t^p\right)^{1/p}.$$

Its derivative with respect to a local score is

$$\frac{\partial S_p}{\partial s_t} =\frac{s_t^{p-1}}{\left(\sum_j s_j^p\right)^{(p-1)/p}}.$$

So the induced local weight is proportional to

$$w_t^{(p)}\propto s_t^{p-1}.$$

This is a clean knob:

  • $$p=1$$ treats nonzero evidence roughly uniformly.
  • $$p>1$$ concentrates credit on large local evidence gaps.
  • $$p\to\infty$$ approaches max-like credit on the strongest step.
  • $$p<1$$, if used directly, becomes more diffuse and can overweight small evidence; one must be careful about stability and interpretation.

The mechanism tradeoff is immediate. Concentrated aggregation can reduce credit pollution and sharpen branch updates. But if the evidence score $$s_t$$ is noisy, it can overfit a verifier artifact or teacher quirk. Diffuse aggregation is robust to noisy localization but reinforces more irrelevant tokens.

This is the same geometry as attention over training signal. The question is not “which p is best?” It is: which p gives high gradient alignment with the update you would get from a cleaner on-policy or step-local evaluator, under the rollout distribution you actually have?

Prefix-local KL reveals where the objective moved the policy

If you run two objectives on the same fixed rollout set, final answer accuracy is too coarse. The first diagnostic should be where the policy moved.

Define prefix-local KL after an update:

$$D_t = D_{\mathrm{KL}}\left(\pi_{\theta'}(\cdot\mid h_t)\|\pi_{\theta}(\cdot\mid h_t)\right).$$

For a small natural-gradient step, local KL is approximately quadratic in the local update:

$$D_t \approx \frac{1}{2}\delta z_t^\top F_t\delta z_t,$$

where $$F_t$$ is the softmax Fisher at prefix $$h_t$$. Since $$\delta z_t$$ is driven by $$a_t$$,

$$D_t \propto a_t^2\,\left\|\mathbf{e}_{y_t}-\pi(\cdot\mid h_t)\right\|_{F_t}^2$$

up to parameter sharing and optimizer effects.

That gives a practical measurement: for each objective, plot KL mass over token positions, divergence points, tool events, rubric spans, and high-entropy prefixes. A good sparse-credit objective should move probability near causal branch points, not mostly in formatting, boilerplate, or late answer phrasing.

A related diagnostic is changed-token sparsity:

$$\mathrm{Sparsity}_\epsilon = \frac{1}{T}\sum_t \mathbf{1}[D_t>\epsilon].$$

Low sparsity is not automatically good. It is good only if the changed positions overlap the positions where alternatives actually differ in outcome. Therefore log both:

$$\mathrm{Overlap}_B=\frac{\sum_{t\in B}D_t}{\sum_t D_t}.$$

This is the empirical version of the credit-share equation.

Why fixed-rollout comparisons are the right first experiment

If two methods sample different trajectories, train under different runtimes, and use different verifiers, you cannot tell whether the gain came from exploration, credit aggregation, teacher quality, or serving-path artifacts. The minimal clean object is a fixed candidate set.

For each prompt $$x_i$$, collect candidates

$$\mathcal{Y}_i=\{y_{i1},\ldots,y_{ik}\}$$

with stored token logprobs, prefixes, verifier outcomes, teacher annotations if available, and strategy labels. Then compute objective-induced gradients without initially training:

$$g_m(x_i)=\sum_{y\in\mathcal{Y}_i}\sum_t a^{(m)}_{y,t}\nabla_\theta\log\pi_\theta(y_t\mid h_t),$$

for methods $$m$$ such as outcome-only GRPO-style credit, winner SFT, pairwise DPO, listwise/graph targets, rubric credit, token-level teacher distillation, and p-norm/Hölder-style aggregation.

Now compare:

$$\cos(g_m,g_n),$$

prefix-local KL predicted by each gradient, and which strategies receive mass. Only after this objective-only audit should you run small fine-tunes.

This separates four mechanisms that are otherwise confounded:

  1. Support discovery: did the good strategy appear in the candidate set?
  2. Credit localization: did the objective put gradient on the decisive step?
  3. Aggregation concentration: did the sequence-to-token map spread or focus credit?
  4. Policy movement geometry: did the KL constraint permit the intended local movement?

What to measure

For any RLVR/agent-RL objective comparison, log the sequence-to-token geometry, not just final score:

  1. Candidate support: base rank and probability of successful strategies at divergence prefixes.
  2. Credit vector statistics: $$a_t$$ histograms by position, length, entropy, tool event, and rubric span.
  3. Branch credit share:
$$ \mathrm{Share}_B=\frac{\sum_{t\in B}|a_t|}{\sum_t|a_t|}.$$
  1. Prefix-local KL: before/after or gradient-predicted $$D_t$$ over tokens and event traces.
  2. Changed-token sparsity: fraction of prefixes with KL above a threshold.
  3. Gradient-cosine matrix: objective-induced update directions across DPO/listwise/rubric/teacher/p-norm variants.
  4. Strategy diversity: number of distinct correct strategies whose probability increases, not just final accuracy.
  5. Teacher/verifier staleness: disagreement between fixed teacher labels, updated verifier labels, and on-policy rollouts.
  6. Length and formatting bias: correlation between credit mass and response length, verbosity, boilerplate, or answer format.

Minimal experiment

Build a fixed-rollout audit before running a full RL stack.

  1. Choose a small math/code/tool task set with multiple solution strategies.
  2. Sample $$k$$ rollouts per prompt from one base model; store token logprobs and prefixes.
  3. Label final correctness, rough strategy type, and a small set of causal branch points by diffing successful vs failed traces.
  4. Compute token credit maps for:

- outcome-only uniform sequence credit;

- length-normalized sequence credit;

- pairwise DPO over winner/loser pairs;

- listwise or graph target over candidates;

- rubric/component credit where available;

- token-teacher or self-distilled credit;

- p-norm/Hölder-style concentrated aggregation over local evidence scores.

  1. Without training, compare gradient cosine, branch credit share, predicted prefix-local KL, and strategy mass movement.
  2. Fine-tune tiny adapters or a small model for the top two contrasting credit maps.
  3. Re-sample and ask whether improvements came from more probability on existing correct branches, new strategy discovery, or superficial trace changes.

A useful falsifier for the aggregation-geometry thesis would be:

$$\cos(g_m,g_n)\approx 1$$

and similar prefix-local KL profiles for all credit maps once rollout candidates and verifier labels are fixed. If that happens, the observed method differences probably came from sampling, data, model scale, or implementation details rather than sequence-to-token aggregation.

Failure modes

  1. Credit pollution: success credit reinforces formatting, boilerplate, or lucky but irrelevant tokens.
  2. Credit dilution: decisive branch tokens receive too little update because advantage is spread across long traces.
  3. Unsupported-strategy ceiling: aggregation cannot promote strategies absent from the sampled rollout set.
  4. Teacher staleness: dense token labels copy a teacher's old mistakes or collapse strategy diversity.
  5. Verifier-localization error: rubric or step labels point to plausible explanation spans rather than causal decision points.
  6. Length bias: unnormalized sequence credit over-updates long traces; over-normalization under-updates long but necessary reasoning.
  7. KL-coordinate mismatch: stale old logits or different serving paths make the trust region constrain the wrong local policy.
  8. p-norm over-concentration: max-like aggregation chases a noisy local score and ignores distributed dependencies.
  9. Aggregate metric camouflage: final-answer reward improves while prefix KL moves mainly in style or answer formatting.

MoE Expert Capacity Is an Allocation Problem, Not Just Sparse Compute

Why this concept appeared in the scout

Today's scout had two MoE signals that fit together:

  • UniPool challenges the default design where every transformer layer owns a separate expert set. It instead treats experts as a globally shared pool accessed by layer-specific routers.
  • AllenAI's EMO post frames MoE pretraining as a route to emergent modularity, not merely a serving trick.

The useful refresher is not “what is an MoE layer?” You already know the implementation pattern: route tokens to a small subset of feed-forward experts, combine outputs, add a load/balance loss, hope sparse parameters buy capacity without dense FLOPs.

The foundations question is sharper:

When we say an MoE has “expert capacity,” what resource is being allocated, and what objective makes that capacity specialize rather than blur?

Layer-local MoE answers implicitly: each depth gets its own private expert budget. UniPool asks whether some of that budget is redundant. EMO asks whether pretraining pressure can turn sparse routing into meaningful modularity. Both force the same mathematical view: an MoE is a constrained assignment problem over tokens, layers, experts, and gradients.

The hidden assumption in layer-local experts

Consider a transformer with $L$ MoE feed-forward blocks. In the standard layer-local design, layer $\ell$ has experts

$$E_{\ell,1}, E_{\ell,2}, \ldots, E_{\ell,M}.$$

For token representation $h_{\ell,t}$, a router produces logits

$$z_{\ell,t,j} = r_\ell(h_{\ell,t})_j,$$

probabilities

$$p_{\ell,t,j} = \frac{\exp z_{\ell,t,j}}{\sum_{k=1}^{M}\exp z_{\ell,t,k}},$$

and a sparse selection $S_{\ell,t}$, often top-$k$. The layer output can be written as

$$y_{\ell,t} = \sum_{j \in S_{\ell,t}} \alpha_{\ell,t,j} E_{\ell,j}(h_{\ell,t}),$$

where $\alpha$ is the renormalized gate weight over selected experts.

This architecture assumes the useful expert index is layer-private:

$$\text{expert } j \text{ at layer } \ell \neq \text{expert } j \text{ at layer } \ell'.$$

That assumption may be right if depth changes the feature basis so much that experts cannot be reused. But it may be wasteful if several layers need similar transformations: lexical cleanup, code syntax handling, arithmetic-ish transformations, language/domain adaptation, entity preservation, format control, or rare-feature rescue.

Layer-local MoE pays a parameter bill of roughly

$$\text{expert parameters} \propto L \cdot M \cdot P_E,$$

where $P_E$ is parameters per expert. The local-routing assumption says this bill buys $L \cdot M$ distinct useful modules. The global-pool hypothesis says the effective number of reusable modules may be smaller:

$$M_{\mathrm{effective}} < L \cdot M.$$

The scout-relevant question is not whether perplexity can be preserved. It is whether rare/domain-specific causal features remain attached to clean expert mechanisms when experts are shared globally.

Rewriting MoE as a capacity allocation problem

A global expert pool replaces layer-private experts with

$$E_1, E_2, \ldots, E_G,$$

shared across layers. Each layer still has a router, but the router now chooses from the same pool:

$$p_{\ell,t,g} = \mathrm{softmax}(r_\ell(h_{\ell,t}))_g.$$

The output becomes

$$y_{\ell,t} = \sum_{g \in S_{\ell,t}} \alpha_{\ell,t,g} E_g(h_{\ell,t}).$$

Now the expert budget is not “$M$ experts per layer.” It is “$G$ reusable transformations across depth.” The routing tensor

$$A_{\ell,t,g} \in \{0,1\}$$

says whether token $t$ at layer $\ell$ used expert $g$. Across a batch, this induces a usage matrix

$$U_{\ell,g} = \frac{1}{B T}\sum_{b=1}^{B}\sum_{t=1}^{T} A_{b,\ell,t,g}.$$

For a layer-local MoE, $U_{\ell,g}$ only measures balance within one depth. For a global pool, the full matrix $U \in \mathbb{R}^{L \times G}$ becomes the object of interest.

The global design asks the router to solve a harder allocation problem:

$$\text{assign } (\ell,t) \mapsto g \quad \text{subject to capacity, balance, and usefulness constraints.}$$

That is more expressive in one sense and more dangerous in another. It can reuse modules across depth, but it can also let high-frequency transformations monopolize capacity.

The objective: task loss plus routing regularizers

A sparse MoE usually trains with a main language-model loss plus auxiliary routing losses:

$$\mathcal{L} = \mathcal{L}_{\mathrm{LM}} + \lambda_{\mathrm{bal}}\mathcal{L}_{\mathrm{balance}} + \lambda_z \mathcal{L}_{z} + \cdots.$$

A generic balance term tries to prevent all tokens from collapsing into the same expert. For example, if

$$f_g = \frac{1}{BTL}\sum_{b,\ell,t} A_{b,\ell,t,g}$$

is the realized fraction of assignments to expert $g$, then one possible uniform-load penalty is

$$\mathcal{L}_{\mathrm{balance}} = G \sum_{g=1}^{G} \left(f_g - \frac{1}{G}\right)^2.$$

Real implementations differ, but the geometry is the same: the main loss wants useful routing; the auxiliary loss wants non-collapsed routing. These are not equivalent.

A router can be perfectly balanced and still mechanistically useless. If two experts implement nearly identical transformations, balance only spreads tokens across redundant modules. Conversely, a genuinely specialized rare-feature expert may look imbalanced because the rare feature is rare.

So the important question is not only:

$$\text{Is } f_g \approx 1/G?$$

It is:

$$\text{Does changing expert } g \text{ causally change the feature it appears to specialize in?}$$

That distinction matters more under a global pool, because balance is now global across depths. A global balance term can hide layer-specific starvation: the expert may be well-used overall while being unavailable or ineffective at the depth where a rare feature needs it.

Router gradients: why specialization can be fragile

Let expert outputs be combined densely for the derivation, then sparsified in practice:

$$y = \sum_{g=1}^{G} p_g E_g(h).$$

Let the downstream loss for this token be $\mathcal{L}$. The derivative with respect to router logit $z_g$ follows from the softmax Jacobian:

$$\frac{\partial p_i}{\partial z_g} = p_i(\mathbf{1}_{i=g} - p_g).$$

Then

$$\frac{\partial \mathcal{L}}{\partial z_g} = \sum_i \frac{\partial \mathcal{L}}{\partial y}^\top E_i(h) \frac{\partial p_i}{\partial z_g}.$$

So

$$\frac{\partial \mathcal{L}}{\partial z_g} = p_g \frac{\partial \mathcal{L}}{\partial y}^\top \left(E_g(h) - \sum_i p_i E_i(h)\right).$$

Define the mixture output

$$\bar{E}(h)=\sum_i p_i E_i(h).$$

Then the router gradient is

$$\frac{\partial \mathcal{L}}{\partial z_g} = p_g \left\langle \nabla_y \mathcal{L}, E_g(h)-\bar{E}(h) \right\rangle.$$

This equation is the router-specialization mechanism in miniature.

An expert receives higher router probability when its output differs from the current mixture in a direction that reduces loss. If $E_g(h)$ is not distinguishable from the mixture on the examples where it is useful, the router has weak evidence to select it. If the feature is rare, the corresponding gradient appears rarely. If top-$k$ gating excludes the expert early, it may receive little or no expert-gradient on precisely the examples where it should specialize.

Sparse routing sharpens the issue. With hard top-$k$, many experts have

$$A_g = 0,$$

so their expert weights receive no main-loss gradient for that token:

$$\nabla_{\phi_g}\mathcal{L}_{\mathrm{LM}} = 0 \quad \text{if expert } g \text{ is not selected.}$$

The router is therefore both a compute allocator and a gradient allocator.

This is the first-principles reason MoE modularity is not automatic. The model cannot make an expert specialize in examples that the router rarely sends to it, and the router cannot confidently send examples to an expert before that expert has become useful. Auxiliary losses, router noise, warm starts, shared pools, normalization, and capacity factors are all hacks around this chicken-and-egg geometry.

Global sharing changes the gradient mixture

For layer-local experts, expert $E_{\ell,j}$ sees gradients only from layer $\ell$:

$$\nabla_{\phi_{\ell,j}}\mathcal{L} = \sum_{b,t: j \in S_{b,\ell,t}} \nabla_{\phi_{\ell,j}}\mathcal{L}_{b,\ell,t}.$$

For a globally shared expert $E_g$, gradients arrive from many depths:

$$\nabla_{\phi_g}\mathcal{L} = \sum_{b,\ell,t: g \in S_{b,\ell,t}} \nabla_{\phi_g}\mathcal{L}_{b,\ell,t}.$$

This can be good if the same transformation is genuinely reusable. It increases effective data per expert and reduces redundant parameters.

But it can be bad if different layers send incompatible gradients. A useful diagnostic is gradient alignment across layers for the same expert:

$$\cos_{g}(\ell,\ell') = \frac{\langle \nabla_{\phi_g}^{(\ell)}\mathcal{L},\nabla_{\phi_g}^{(\ell')}\mathcal{L}\rangle} {\|\nabla_{\phi_g}^{(\ell)}\mathcal{L}\|\,\|\nabla_{\phi_g}^{(\ell')}\mathcal{L}\|}.$$

If this cosine is positive across the layers that share an expert, global pooling is acting like data amplification for a reusable module. If it is near zero, the expert may become a generic compromise. If it is negative, sharing creates direct interference.

This gives a more mechanistic test than validation loss:

$$\text{global pool works mechanistically} \quad \Rightarrow \quad \text{shared expert gradients are aligned for the factors they serve.}$$

Capacity constraints and rare-feature starvation

MoE routing also has capacity constraints. If each expert can process at most $C$ token assignments in a batch, then expert $g$ drops or reroutes overflow tokens when

$$\sum_{b,\ell,t} A_{b,\ell,t,g} > C.$$

A common capacity form is proportional to average load:

$$C = \gamma \frac{BTLk}{G},$$

where $\gamma$ is the capacity factor and $k$ is top-$k$ routing.

The rare-feature failure mode is subtle. Suppose a rare feature $x^\star$ appears in only a small fraction of tokens, but requires a specific expert transformation. If the expert also attracts many high-frequency tokens, then rare tokens may be displaced by capacity pressure. Even when they are not dropped, their gradients can be drowned by common-token gradients.

The signal-to-interference ratio for a rare feature routed to expert $g$ is roughly

$$\mathrm{SIR}_{g,x^\star} = \frac{\left\|\sum_{(b,\ell,t) \in R_{x^\star,g}} \nabla_{\phi_g}\mathcal{L}_{b,\ell,t}\right\|} {\left\|\sum_{(b,\ell,t) \in R_{\neg x^\star,g}} \nabla_{\phi_g}\mathcal{L}_{b,\ell,t}\right\| + \epsilon}.$$

A global pool can improve this if it routes all occurrences of the rare feature across depths into a stable module. It can worsen it if the shared expert becomes a dumping ground for broad high-frequency transformations.

That is why a MoE can match perplexity while degrading rare-feature causality. Perplexity is dominated by common tokens; causal expert specialization is often about low-measure slices.

What “emergent modularity” should mean operationally

A vague modularity claim is easy to make: experts appear to route different domains, languages, or formats. A useful claim should survive interventions.

For a factor $F$ such as language, code syntax, domain, rare entity type, or arithmetic pattern, define the conditional routing distribution

$$P(g \mid F, \ell) = \frac{\sum_{b,t} A_{b,\ell,t,g}\mathbf{1}[F_{b,t}=1]} {\sum_{b,t}\mathbf{1}[F_{b,t}=1]}.$$

A basic specialization score is mutual information:

$$I(G;F \mid \ell) = \sum_{g,f} P(g,f\mid \ell) \log \frac{P(g,f\mid \ell)}{P(g\mid \ell)P(f\mid \ell)}.$$

But routing correlation is not enough. We also want causal dependence. Ablate expert $g$ or route factor-$F$ tokens away from it, then measure the feature-specific loss increase:

$$\Delta_{g,F} = \mathbb{E}_{x \sim F}[\mathcal{L}(x; \mathrm{ablate}\ g)] - \mathbb{E}_{x \sim F}[\mathcal{L}(x; \mathrm{baseline})].$$

A real module should have both:

$$I(G;F \mid \ell) \text{ high} \quad \text{and} \quad \Delta_{g,F} \text{ high on the intended factor.}$$

If $I$ is high but $\Delta$ is low, routing is decorative. If $\Delta$ is high but $I$ is low, the factor may be distributed across experts. If both are low while perplexity is good, the model may be using dense residual pathways or shared generic experts rather than modular specialization.

Why global pools are an especially good small-model experiment

This topic is experimentally attractive because the toy setup can have known ground-truth factors.

Create synthetic sequences with factors like:

  • domain: natural language vs code-like grammar vs arithmetic strings
  • rare exception: a low-frequency token class requiring a different mapping
  • position rule: early vs late token dependency
  • format rule: JSON-like bracket closure vs prose continuation

Train two small models under equal active compute:

  1. layer-local MoE: $L$ layers, $M$ experts per layer
  2. global-pool MoE: $L$ layers, $G < L M$ shared experts

Match active experts per token and approximate FLOPs. Then compare not only validation loss, but the mechanism:

$$U_{\ell,g},\quad I(G;F\mid \ell),\quad \Delta_{g,F},\quad \cos_g(\ell,\ell'),\quad \text{rare-feature accuracy}.$$

The interesting result would not be “global pooling wins.” The interesting result would be a map of when sharing helps and when it causes interference.

A plausible hypothesis:

  • global pooling helps when a feature needs the same transformation at several depths;
  • layer-local experts help when depth-specific transformations have conflicting gradients;
  • rare features need either protected routing, expert capacity, or loss weighting, otherwise they disappear under common-token load.

What to measure

For a MoE expert-allocation study, measure these directly:

  1. Routing usage matrix
$$ U_{\ell,g} = \frac{1}{BT}\sum_{b,t} A_{b,\ell,t,g}.$$

Look for collapsed experts, depth-specific experts, and globally reused experts.

  1. Router entropy by factor and layer
$$ H(G\mid F,\ell) = -\sum_g P(g\mid F,\ell)\log P(g\mid F,\ell).$$

Low entropy may indicate specialization; it may also indicate collapse.

  1. Factor-routing mutual information
$$ I(G;F\mid \ell).$$

Use it as a correlation screen, not final evidence.

  1. Causal expert ablations
$$ \Delta_{g,F} = \mathbb{E}_{x \sim F}[\mathcal{L}(x; \mathrm{ablate}\ g)] - \mathbb{E}_{x \sim F}[\mathcal{L}(x)].$$

This is the key modularity test.

  1. Cross-layer gradient cosine for shared experts
$$ \cos_g(\ell,\ell') = \frac{\langle \nabla_{\phi_g}^{(\ell)}, \nabla_{\phi_g}^{(\ell')}\rangle} {\|\nabla_{\phi_g}^{(\ell)}\|\,\|\nabla_{\phi_g}^{(\ell')}\|}.$$

This tells you whether sharing is reuse or interference.

  1. Rare-feature retention under equal loss

Slice evaluation by low-frequency factors. Do not trust aggregate perplexity alone.

Minimal experiment

Build a tiny decoder-only LM with MoE MLP blocks. Use a synthetic dataset with three factor families:

  • common grammar tokens;
  • domain-specific subsequences;
  • rare exception tokens requiring a different local rule.

Train these variants with matched active compute:

  1. dense MLP baseline;
  2. layer-local top-1 or top-2 MoE;
  3. globally shared expert pool;
  4. global pool with a stronger balance/capacity setting;
  5. optional protected rare-feature routing or rare-slice loss weighting.

Log:

  • train/validation loss;
  • per-factor accuracy;
  • $U_{\ell,g}$ heatmaps;
  • $I(G;F\mid\ell)$;
  • expert ablation losses $\Delta_{g,F}$;
  • cross-layer gradient cosine for shared experts;
  • dropped-token or overflow rate by factor.

The falsifier for the global-pool story is clean: if the shared-pool model matches loss but has lower factor-routing mutual information, weaker causal ablation effects, worse rare-feature accuracy, or negative cross-layer gradient alignment, then parameter savings are hiding modularity loss.

Failure modes

  1. Balanced but non-modular routing. The auxiliary loss can distribute tokens evenly without producing meaningful experts.
  1. Decorative specialization. Experts correlate with factors, but ablating them does not affect those factors.
  1. Common-token monopolies. High-frequency transformations dominate shared experts, drowning rare-feature gradients.
  1. Cross-layer interference. A global expert receives incompatible gradients from different depths and becomes a compromise transformation.
  1. Capacity artifacts. Rare features look hard only because they overflow or are dropped under capacity constraints.
  1. Dense-path leakage. Residual streams or attention heads solve the task while MoE routing looks interpretable but is not causal.
  1. Perplexity camouflage. Aggregate loss improves while low-frequency/domain-specific features get worse.

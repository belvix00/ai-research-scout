Runtime-Certified Attention: Turning Quantization Error Into a Decision Margin

Why this concept appeared in the scout

The 2026-05-23 scout had a strong inference-systems cluster:

  • Runtime-Certified Bounded-Error Quantized Attention reframed low-bit attention as something that should come with a per-instance error certificate, not just a good average benchmark.
  • OCTOPUS and related KV-cache compression work made cache/state compression part of the model’s decision geometry.
  • The running scout notes already treat deployment paths as causal transformations: fp16, quantized weights, quantized KV, sparse attention, runtime LoRA, MLX/ExecuTorch/vLLM, and browser/WebGPU paths are not transparent serialization formats.

The useful foundations refresher is not “what is quantization?” The important object is the margin between the exact attention computation and the deployed approximation. A low-bit attention path is safe for a particular token only if its error is smaller than the task-relevant margin.

Averages can hide this. Perplexity can barely move while a rare early clue loses to a distractor because the deployed path perturbed one key logit by a few tenths. The scout question is therefore:

Can runtime error certificates predict when quantized attention/KV compression will preserve the evidence binding that matters for a decision?

The exact attention object we are perturbing

For one attention head, write the exact attention output for query $$q$$, keys $$k_i$$, and values $$v_i$$ as

$$z_i = \frac{q^\top k_i}{\sqrt d}, \qquad \alpha_i = \frac{e^{z_i}}{\sum_j e^{z_j}}, \qquad y = \sum_i \alpha_i v_i.$$

A quantized or compressed path replaces some part of this computation:

$$q \mapsto \hat q, \qquad k_i \mapsto \hat k_i, \qquad v_i \mapsto \hat v_i, \qquad z_i \mapsto \hat z_i, \qquad y \mapsto \hat y.$$

The deployed output error is

$$\Delta y = \hat y - y.$$

But output norm alone is not enough. If the answer depends on choosing the true evidence token $$*$$ over distractors $$d\in D$$, the more relevant quantity is the attention margin

$$M = z_* - \max_{d\in D} z_d$$

or, with many distractors, the log-sum-exp margin

$$M_{\mathrm{eff}} = z_* - \log \sum_{d\in D} e^{z_d}.$$

Quantization is harmless for this decision if the perturbation cannot flip the sign of the relevant margin.

From vector quantization error to logit error

Suppose the deployed path has bounded query/key errors

$$\hat q = q + \delta q, \qquad \hat k_i = k_i + \delta k_i.$$

The deployed logit is

$$\hat z_i = \frac{(q+\delta q)^\top(k_i+\delta k_i)}{\sqrt d}.$$

So the logit perturbation is

$$\Delta z_i = \hat z_i-z_i = \frac{q^\top\delta k_i + k_i^\top\delta q + \delta q^\top\delta k_i}{\sqrt d}.$$

By Cauchy-Schwarz,

$$|\Delta z_i| \le \frac{\|q\|\,\|\delta k_i\| + \|k_i\|\,\|\delta q\| + \|\delta q\|\,\|\delta k_i\|}{\sqrt d}.$$

If runtime metadata can bound

$$\|\delta q\|\le \epsilon_q, \qquad \|\delta k_i\|\le \epsilon_{k,i},$$

then it can emit a logit-error certificate

$$|\Delta z_i| \le b_i = \frac{\|q\|\epsilon_{k,i}+\|k_i\|\epsilon_q+\epsilon_q\epsilon_{k,i}}{\sqrt d}.$$

This is the first key mechanism: a quantization method is not merely “4-bit” or “8-bit.” For a specific token, head, and prompt, it induces a local logit uncertainty interval

$$\hat z_i \in [z_i-b_i, z_i+b_i]$$

or, if the exact logit is not computed, an interval around an approximate logit using a conservative bound.

A certificate for preserving the winning evidence token

For one evidence token $$*$$ and one distractor $$d$$, the exact margin is

$$M_{*d}=z_*-z_d.$$

The deployed margin is

$$\hat M_{*d}=\hat z_* - \hat z_d = M_{*d} + \Delta z_* - \Delta z_d.$$

If

$$|\Delta z_*|\le b_* , \qquad |\Delta z_d|\le b_d,$$

then

$$\hat M_{*d} \ge M_{*d} - b_* - b_d.$$

So a sufficient condition for preserving the pairwise ordering is

$$M_{*d} > b_*+b_d.$$

With multiple distractors, a conservative certificate is

$$z_* - z_d > b_*+b_d \qquad \forall d\in D.$$

This is stricter than necessary but interpretable. It says: the evidence logit is separated from every distractor by more than the maximum quantization-induced margin shrinkage.

For the log-sum-exp version, define the approximate distractor mass

$$L_D = \log \sum_{d\in D} e^{z_d}.$$

If all distractor logits may increase by their bounds and the evidence logit may decrease by its bound, a worst-case deployed effective margin is

$$\hat M_{\mathrm{eff}} \ge z_* - b_* - \log\sum_{d\in D} e^{z_d+b_d}.$$

A runtime certificate can therefore report

$$C_{\mathrm{eff}} = z_* - b_* - \log\sum_{d\in D} e^{z_d+b_d}.$$

If

$$C_{\mathrm{eff}}>0,$$

then quantization cannot make the aggregate distractor set beat the evidence under the stated logit bounds.

Why softmax makes the certificate decision-dependent

Attention output error is not linear only because logits change; softmax amplifies some perturbations and suppresses others. Let

$$\alpha = \mathrm{softmax}(z).$$

The Jacobian is

$$\frac{\partial \alpha_i}{\partial z_j} = \alpha_i(\mathbf 1_{i=j}-\alpha_j).$$

For a small logit perturbation $$\Delta z$$,

$$\Delta \alpha_i \approx \alpha_i\left(\Delta z_i - \sum_j \alpha_j\Delta z_j\right).$$

So perturbing a token with negligible attention may not matter. Perturbing a near-tie among evidence-bearing tokens can matter a lot. The pairwise two-token case is especially clear:

$$P(*)=\sigma(M), \qquad \frac{\partial P(*)}{\partial M}=\sigma(M)(1-\sigma(M)).$$

The derivative is largest when $$M\approx 0$$. That is exactly the regime where rare evidence, stale corrections, or low-salience early facts compete with plausible distractors.

This is why aggregate quantization metrics underweight the dangerous cases. Most tokens may have large margins or irrelevant perturbations. The failures concentrate where the model was already uncertain and the exact computation barely preserved the correct binding.

Value-vector error: preserving the winner is not enough

Even if quantization preserves the attention ordering, value compression can change the retrieved information. Write

$$\hat v_i = v_i + \delta v_i.$$

The deployed output is

$$\hat y = \sum_i \hat \alpha_i \hat v_i.$$

Subtract the exact output:

$$\hat y-y = \sum_i (\hat\alpha_i-\alpha_i)v_i + \sum_i \hat\alpha_i \delta v_i.$$

The first term is attention distribution drift. The second is value reconstruction error. A simple bound is

$$\|\hat y-y\| \le \sum_i |\hat\alpha_i-\alpha_i|\,\|v_i\| + \sum_i \hat\alpha_i\|\delta v_i\|.$$

For rare evidence, the second term matters because the decisive content can be low-energy in average reconstruction terms. A KV codec can preserve most value dimensions while damaging the subspace that carries the rare clue.

If the downstream residual/logit readout for an answer contrast is approximately a vector $$u$$, then the relevant scalar is not $$\|\Delta y\|$$ but

$$\Delta m = u^\top(\hat y-y).$$

A value-error certificate should ideally bound

$$|u^\top(\hat y-y)|$$

or a proxy for task-relevant subspaces, not only MSE over cached values.

Three levels of certification

Runtime certificates can be useful at different strengths.

1. Numeric certificate

This certifies that the approximate attention output is close to exact attention:

$$\|\hat y-y\|\le \epsilon_y.$$

This is helpful for debugging and fallback decisions, but it is not directly a behavioral guarantee.

2. Ordering certificate

This certifies that the evidence token remains above distractors:

$$z_* - z_d > b_*+b_d \qquad \forall d\in D.$$

This is better for rare-evidence tasks because it targets the attention decision.

3. Behavior-margin certificate

This certifies that the final answer margin survives the deployed approximation. If the exact answer contrast is

$$S = \ell_{\mathrm{answer}} - \ell_{\mathrm{competitor}},$$

and the runtime path can bound the final contrast perturbation by $$B_S$$, then

$$S>B_S$$

is the decision-level certificate.

This is hardest to compute but closest to what we care about. In practice, a cheap harness can log all three proxies: attention logit bounds, output drift, and answer logit margin.

Why runtime certification is different from post-hoc eval

A normal eval says: “this quantized model got 82%.” A runtime certificate says: “on this prompt, this head/layer/token decision had error budget $$b$$ and margin $$M$$.”

That distinction matters for deployment because failures are instance-specific. The same quantized path can be safe for short, redundant prompts and unsafe for long contexts with repeated aliases. A good runtime policy can do something with this information:

  • accept the fast low-bit path when the certificate is strong;
  • recompute selected heads/tokens in higher precision when the certificate is weak;
  • preserve uncompressed KV for rare high-risk spans;
  • route uncertain prompts to a slower backend;
  • log certificate failures as benchmark slices.

In other words, certification turns quantization from a static model choice into an adaptive systems policy.

The optimization geometry view

Quantization is often described as minimizing reconstruction loss:

$$\min_{\hat W\in\mathcal Q}\|W-\hat W\|^2$$

or some activation-weighted version. For attention/KV, the decision-relevant objective is closer to preserving margins:

$$\min_{\mathrm{quantizer}}\;\mathbb E_x\left[\max\left(0, B(x)-M(x)\right)\right],$$

where $$M(x)$$ is the exact decision margin and $$B(x)$$ is the runtime error bound under the deployed approximation.

This changes the geometry. A reconstruction-optimal quantizer may spend bits on high-variance common directions. A certificate-aware quantizer should spend bits where small errors threaten small margins:

$$\text{risk}(x) = \frac{B(x)}{|M(x)|+\eta}.$$

High risk does not necessarily mean high norm. It means the approximation error is large relative to the margin needed for the decision.

For long-context evidence, this suggests a useful policy: preserve precision around tokens with high evidence potential and low binding margin, not merely tokens with high activation norm or recent position.

What to measure

For a runtime-certified attention/KV audit, log quantities that connect low-level error to decision survival:

  1. Per-token logit error bounds: $$b_i$$ for attention logits, by layer/head/token.
  2. Evidence margin: $$M=z_ - \max_d z_d$$ and $$M_{\mathrm{eff}}=z_ - \log\sum_d e^{z_d}$$.
  3. Certificate slack:
$$ \mathrm{slack}=M-(b_*+b_{d^*})$$

or the log-sum-exp certificate $$C_{\mathrm{eff}}$$.

  1. Attention drift: $$\|\hat\alpha-\alpha\|_1$$ on evidence/distractor spans.
  2. Value drift: $$\|\hat y-y\|$$ plus task-projected drift if answer-logit contrasts are available.
  3. Answer margin survival: exact vs deployed logit margin for the correct answer.
  4. Rare-slice failures: early clue, stale correction, negative evidence, low-frequency name/entity, repeated distractor templates.
  5. Fallback rate: fraction of prompts/tokens where the certificate is uncertain and higher precision would be triggered.
  6. Cost tradeoff: latency, memory, KV bytes, bandwidth, and recomputation overhead per certified-safe decision.

Minimal experiment

Build a small long-context rare-evidence harness and compare exact vs approximate attention paths.

  1. Use one local model where logprobs or attention/logit proxies are accessible.
  2. Construct prompts with:

- one true early clue;

- several semantically similar distractors;

- stale corrections;

- rare names/entities;

- position-swapped variants.

  1. Run at least three paths:

- fp16/bf16 baseline;

- quantized attention or quantized KV path;

- quantized path with a conservative fallback rule if certificate slack is negative.

  1. For each prompt, record exact answer logprob margin where possible and deployed answer margin always.
  2. Approximate certificate risk even if the paper’s full method is not implemented: use measured logit drift between exact and deployed runs as empirical $$b_i$$, then test whether low slack predicts failures.
  3. Plot failure probability against
$$ \mathrm{risk}=\frac{B}{|M|+\eta}.$$

The cheap falsifier is strong: if certificate slack or empirical risk does not predict rare-evidence failures better than aggregate perplexity, output drift, or context length, then certification may not be the right sign-off layer for this setting.

Failure modes

  1. Certificate bound is too loose. If $$B$$ is always huge, everything falls back and the certificate is operationally useless.
  2. Certificate bound is too local. A head-level attention guarantee may not bound downstream residual, MLP, or final answer behavior.
  3. Wrong evidence span. The harness may label the evidence token, but the model may use another correlated cue.
  4. Attention preservation without value preservation. The model attends to the right KV slot but compressed values lose the decisive feature.
  5. Value preservation without answer survival. Small hidden-state drift can still flip a close final logit margin.
  6. Average reconstruction wins the wrong objective. Low MSE can coexist with high margin risk on rare slices.
  7. Fallback hides the problem. A fallback policy can restore accuracy while making latency unpredictable; log fallback rate and tail latency.
  8. Serving stack confounds. Batching, prefill/decode split, cache layout, speculative decoding, and runtime kernels can all change drift independently of nominal quantization.

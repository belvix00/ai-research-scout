AI Research Scout — 2026-05-05 2nd run

What happened today

This manual second run used the newer broad-but-scoped resource policy: deep learning, LLMs, training dynamics, RL, mechanistic interpretability, audio/TTS, inference systems, ML infra, and GPUs. It intentionally avoids GitHub issue/release firehoses and broad robotics/control/database drift.

The collected resources suggest three useful scanning directions: recent papers remain the highest-density source for mechanisms, lab/infra blogs are better for understanding what has become cheap to run, and weak signals should stay weak unless they connect to a concrete model/training/inference failure mode.

Pattern / mechanism thesis

The recurring pattern is interface pressure: modern ML systems are increasingly limited by interfaces between components — tokenizer to model, prefill to decode, training objective to representation, codec to acoustic detail, and interpretability probe to latent feature geometry. For learning, the useful move is not to overfit this to one personal project, but to ask where information, gradients, memory, or compute are being compressed or routed badly.

2. Build an inference/GPU reading lane separate from model-paper reading

  • Evidence / source links:

- See infra/GPU resources in 2026-05-05-2nd-run-2317-IST.md.

  • Mechanism:

- Inference systems have their own concepts: prefill/decode split, KV-cache layout, kernel fusion, quantization formats, bandwidth ceilings. Mixing these with paper summaries makes them look like implementation details, but they often decide what experiments are cheap.

  • Minimal experiment / probe:

- Maintain a small inference concepts queue: KV cache, prefill/decode, FlashAttention, FP8/INT4, speculative decoding, batching. Each blog post should connect one concept to a tiny benchmark.

  • Falsifier:

- If infra concepts do not change experiment choices after two weeks, reduce their quota.

  • Confidence: medium

3. Add a low-personalization learning lane

  • Evidence / source links:

- This run marks most resources as Personalization: low.

  • Mechanism:

- If every resource is interpreted through past projects, the scout collapses into confirmation bias. Low-personalization resources preserve exploration while staying inside DL/LLM/audio/RL/mech-interp/inference.

  • Minimal experiment / probe:

- In weekly synthesis, include a section: What did I learn that was not obviously connected to my current projects?

  • Falsifier:

- If this section stays empty or irrelevant for a month, retune source mix.

  • Confidence: high

4. Separate skeptical/failure signals from opportunities

  • Evidence / source links:

- Weak signals and critique/newsletter sources in the resources page.

  • Mechanism:

- Negative evidence often protects attention better than positive hype. A failed reproduction, benchmark caveat, or infra pain point can be more valuable than another paper title.

  • Minimal experiment / probe:

- Add a skeptical or failure signal slot to daily resources, but only promote it to daily briefing if it changes what to test or avoid.

  • Falsifier:

- If skeptical signals become generic negativity, remove the slot.

  • Confidence: medium

5. Track audio/TTS as a first-class lane, not a side topic

  • Evidence / source links:

- See eess.AS / speech-related resources in 2026-05-05-2nd-run-2317-IST.md.

  • Mechanism:

- Audio models have different bottlenecks than text LMs: codec latents, speaker/prosody disentanglement, continuous-vs-discrete acoustic state, latency, and long-form drift.

  • Minimal experiment / probe:

- Maintain one daily resource slot for audio/TTS when a quality item exists; weekly synthesize whether any representation/training issue repeats.

  • Falsifier:

- If the lane mostly produces demos without mechanisms, narrow it to papers/technical reports only.

  • Confidence: medium
